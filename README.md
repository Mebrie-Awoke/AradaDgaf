# AradaDgaf — IT Support Ticketing System

## Backend

The backend is a Django REST Framework API. PyMongo stores all application records in MongoDB Atlas. Django's local SQLite database is used only by Django's built-in admin/session framework; it does not store application users, tickets, comments, or other AradaDgaf records.

MongoDB collections, validators, and indexes are created automatically by the versioned migration runner on the first database-backed request. The public `/api/health/` endpoint is a liveness check only; database-backed endpoints ping Atlas and apply pending migrations.

## Requirements and local setup

- Python 3.11+
- MongoDB Atlas cluster and a least-privilege database user
- Atlas network access configured for the machine running the backend

From the repository root in PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
Copy-Item .env.example .env
```

Edit `.env` locally:
- Set a long, unique `DJANGO_SECRET_KEY`.
- Set `DJANGO_DEBUG=true` for local development.
- Replace the placeholder in `MONGODB_URI` with your Atlas database password.
- Keep `.env` private; it is ignored by Git. Never commit credentials.
- Set exact frontend origins in `CORS_ALLOWED_ORIGINS`.

Run checks and start the API:

```powershell
python backend\manage.py check
python backend\manage.py test core
python backend\manage.py runserver
```

API base URL: `http://127.0.0.1:8000/api/`.

The automated API tests mock MongoDB and do not require a live Atlas connection. A successful `manage.py check` or `/api/health/` response does not prove Atlas connectivity.

## Initial administrator

After configuring a working Atlas connection, create the first administrator interactively:

```powershell
python backend\manage.py create_initial_admin admin@example.com "AradaDgaf Administrator"
```

The password is prompted twice and stored using Django password hashing. The command refuses to create a second initial administrator. Public registration always creates an employee; only administrators can provision other roles.

## Project-paper ticket specification

The ticket document follows Appendix A:
- **Ticket number:** generated by the backend in the sample format `AF-YYYY-NNNNN`.
- **Title and description:** employee-provided; the description should explain the issue, when it started, and any displayed error.
- **Category and department:** optional references to administrator-managed records.
- **Priority:** `low`, `medium`, `high`, or `critical`.
- **Status:** `submitted`, `assigned`, `in_progress`, `resolved`, or `closed`.
- **Created by:** taken from the authenticated account, never trusted from the request.
- **Assigned to:** an active support/admin account or null.
- **Timestamps:** generated by the server.
- **Resolution note:** required before a ticket can be marked resolved.
- **Attachments:** JPEG/PNG images only, size-limited and stored privately; MongoDB stores metadata, not file bytes.

Initial priority ownership, exact status transition policy, employee closure/reopening, attachment restrictions, and internal-comment visibility are proposed defaults that must be confirmed with the IT supervisor as noted in the project paper.

## API conventions

- Success: `{"success": true, "data": ...}`. Paginated results include `meta`.
- Error: `{"success": false, "error": {"detail": ..., "code": ...}}`.
- Protected routes use `Authorization: Bearer <access_token>`.
- Tokens are random opaque values; only SHA-256 digests are stored. Logout revokes the current token.
- Pagination: `?page=1&page_size=25`; page size is capped at 100.
- Roles: `employee`, `support`, and `admin`.
- Employees see only their own tickets. Support/admin can access the support queue. Admin-only operations are protected server-side.

## Endpoints

| Method | Path | Access | Purpose |
|---|---|---|---|
| GET | `/api/health/` | Public | Process liveness |
| POST | `/api/v1/auth/register/` | Public, throttled | Register employee |
| POST | `/api/v1/auth/login/` | Public, throttled | Obtain bearer token |
| POST | `/api/v1/auth/logout/` | Authenticated | Revoke current token |
| GET, POST | `/api/v1/users/` | Admin | List/provision users |
| PATCH | `/api/v1/users/{user_id}/` | Admin | Update role, department, name, or active state |
| GET | `/api/v1/admin/audit/` | Admin | Review privileged administrative changes |
| GET | `/api/v1/dashboard/` | Authenticated | Ticket totals by status/priority and unread count |
| GET, POST | `/api/v1/departments/` | Authenticated / Admin | List/create departments |
| PATCH | `/api/v1/departments/{id}/` | Admin | Edit/deactivate department |
| GET, POST | `/api/v1/categories/` | Authenticated / Admin | List/create categories |
| PATCH | `/api/v1/categories/{id}/` | Admin | Edit/deactivate category |
| GET, POST | `/api/v1/tickets/` | Authenticated | List/filter or submit ticket |
| GET, PATCH | `/api/v1/tickets/{id}/` | Owner, support, admin | View/update ticket |
| GET, POST | `/api/v1/tickets/{id}/comments/` | Owner, support, admin | List/add public or internal comments |
| GET | `/api/v1/tickets/{id}/audit/` | Owner, support, admin | Read ticket history |
| GET, POST | `/api/v1/tickets/{id}/attachments/` | Owner, support, admin | List/upload image |
| GET | `/api/v1/tickets/{id}/attachments/{attachment_id}/download/` | Owner, support, admin | Download private attachment |
| GET | `/api/v1/notifications/` | Authenticated | List own notifications; `?unread=true` filters |
| PATCH | `/api/v1/notifications/{id}/` | Notification owner | Mark notification as read |

## Example requests

Register:

```http
POST /api/v1/auth/register/
Content-Type: application/json

{"email":"alex@example.com","name":"Alex Rivera","password":"Correct-Horse-Battery-42!"}
```

Submit a ticket (the API supplies its number, owner, status, and timestamps):

```http
POST /api/v1/tickets/
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "title": "Printer is not responding",
  "description": "The Finance office printer stopped working this morning and displays a paper-feed error.",
  "category_id": "<category-object-id>",
  "department_id": "<department-object-id>",
  "priority": "medium"
}
```

Resolve a ticket:

```http
PATCH /api/v1/tickets/<ticket-id>/
Authorization: Bearer <support-access-token>
Content-Type: application/json

{
  "status": "resolved",
  "resolution_note": "Cleared the paper-feed obstruction and tested a print successfully."
}
```

Add an internal support note:

```http
POST /api/v1/tickets/<ticket-id>/comments/
Authorization: Bearer <support-access-token>
Content-Type: application/json

{"body":"Waiting for replacement toner from stores.","internal_only":true}
```

Uploads use multipart form field `file`. The API checks extension, declared MIME type, file signature, filename, and size. It creates a random storage key; clients cannot supply or retrieve that key. Configure `PRIVATE_STORAGE_BACKEND` and `PRIVATE_STORAGE_OPTIONS` to use a durable private storage service in deployment. The default local FileSystemStorage path must be on a private durable volume and must never be served as public media.

## MongoDB schema and migrations

Versioned migrations live in `backend/core/mongo_migrations/` and are recorded in the `schema_migrations` collection. They create collections, JSON Schema validators, unique/query indexes, and migrate legacy ticket values. Current collections include users, access tokens, tickets, counters, departments, categories, ticket comments, ticket audit events, attachments, notifications, administrative audit events, and schema migration history.

Add a new forward-only migration for future schema changes; do not edit an already-applied migration. Back up MongoDB and private attachment storage before applying production schema changes. The migration runner is idempotent and runs before database-backed requests.

## Security and deployment

- Use a least-privilege Atlas user restricted to the application database and restrict Atlas network access.
- Keep secrets in environment variables or a deployment secret manager; never commit `.env`.
- Set `DJANGO_DEBUG=false`, exact `DJANGO_ALLOWED_HOSTS`, exact CORS origins, and a production secret key.
- Enable HTTPS redirect/HSTS only when proxy TLS termination is configured correctly.
- Keep attachments in private, durable storage and back up both MongoDB metadata and file bytes.
- Run `python backend\manage.py check --deploy` and `python backend\manage.py test core` in CI before release.
- Monitor database/storage failures and document backup/restore procedures.
